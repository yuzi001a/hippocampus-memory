## Canonical design
1. Canonical durable data remains `explicit_memories`; raw `conversation_stream` and `qa_pairs` are not edited or deleted by corrections.
2. Additive `memory_relations` sidecar has `relation_id`, `from_memory_id`, nullable `to_memory_id`, `relation_type`, real correction provenance, `correction_reason`, `effective_at`, server `recorded_at`, and deterministic normalized request. No conversation-stream UPDATE to add memory relation fields.
3. Relations are `supersedes` (replace, nonnull different successor) or `withdraws` (no successor). Unique outgoing/incoming constraints prevent branching. Reader independently refuses corrupt cycles/missing endpoints; constraints alone do not establish acyclicity.
4. `ActiveMemoryWriter.correct(memory_id, replacement_content=None, *, mode='replace', replacement_title=None, replacement_tags=None, correction_reason=None, correction_source_id=None, effective_at=None, authority=None)` is the only canonical mutation seam. Modes are replace/withdraw; authority is `user_explicit` for both.
5. Replace locks the target, validates actual canonical state/source and idempotency, archives old without changing its immutable content, inserts a new version and relation, then commits once. Any precommit error rolls back all three effects. A→B→A-content creates a new version, never reactivates an old payload.
6. Withdraw locks/archives the old version and inserts a withdrawal relation in the same transaction, creates no replacement and calls no embedding. Supplied replacement fields in withdraw mode are refused.
7. Identical normalized requests produce zero new writes. Different requests against an already-corrected/withdrawn target report conflict with the actual terminal current ID (possibly null), not a stale intermediate version. Retries report original replacement ID plus its actual status after subsequent corrections.
8. A supplied correction source must be literal ASCII digits identifying a real user `conversation_stream` row. Record that event and its available session/host provenance; missing source is explicitly `explicit_tool_request`, not a fabricated conversation reference. No identity token stripping or repair.
9. Verify committed old/new immutable payloads (including old provenance for replace and withdraw), actual relation and actual terminal/status in one fresh coherent storage snapshot before claiming verified success. Return actual `recorded_at`; never hardcode an intermediate successor as active after a concurrent follow-up. Precommit failure reports durable=false; indeterminate COMMIT reports durable=null with an explicit uncertainty error; known-commit cleanup/readback failure reports durable=true with explicit verification failure. Public tool forwarding preserves this tri-state verbatim. Derived embedding failure warns without rolling back durable state; withdrawal has no embedding.
10. Reader uses a coherent read-only database snapshot (or equivalent atomic query). Current resolution returns only a truly active terminal version; archived-without-successor and withdrawal return no current memory. History selects the exact requested payload and exposes the ordered full ancestor/successor chain with accurate archived/current/superseded/withdrawn labels.

## Public tools
- Extend existing `v3_update`: `action='correct'`, `memory_id`, `mode='replace'|'withdraw'` (omitted=replace), replacement fields, correction reason, source, effective time. No standalone correction tool or adapter-specific protocol.
- Extend existing `v3_get`: `target='memory'`, `memory_id`, `mode='current'|'history'`, `include_history`. Existing `hm` forwards explicitly supplied read options using the same canonical resolver.
- Plain active `hm_get` retains the legacy 9-column active-memory payload unchanged. Canonical nested results are rendered from `memory` for current and `requested` for history. `include_history` does not silently change current mode; no-current never leaks archived payload as current.
- Injected booted runtime/core/profile/PG/config is authoritative and must not silently fall back to default-profile configuration; this includes a core constructed by the unified-read entrypoint. A supplied booted `core` **is** the runtime authority and is never refused merely for being supplied — its own `.pg`/`.config` are used directly. The fail-closed refusal is therefore scoped to the places where a default profile would actually be resolved: a declared-but-empty `effective_config`, a declared runtime with no core, and the card-file fallback that would otherwise call `resolve_config()`. It must never refuse a read whose path needs neither a pool nor a config (an active explicit-memory exact hit read through `core.pg`, or the handbook fallback via `handbook_manager(current_scope())`). Explicitly supplied null/invalid mode or history flags fail before I/O, while omitted parameters retain legacy defaults. Preserve canonical status/durable/error-code/relation fields honestly. Snapshot transactions must exit/rollback before their lease is released.
